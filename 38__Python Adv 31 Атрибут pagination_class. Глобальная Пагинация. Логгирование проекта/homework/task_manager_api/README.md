# Менеджер задач — пагинация и логирование

Глобально подключён `ProjectCursorPagination` на основе `CursorPagination`.
Списки задач, подзадач, категорий и результат `/api/categories/count-tasks/`
возвращают не более **6 объектов** на странице. Локальная пагинация подзадач
заменена глобальной. `page_size`, `page`, `limit` и `offset` не увеличивают размер.

## Выбор пагинации

Курсор передаёт непрозрачную позицию перехода вместо явного номера страницы
или смещения. Это соответствует требованию не показывать такие параметры
напрямую. Курсор не зашифрован, не является секретом и не заменяет авторизацию.
Его нельзя считать самостоятельной защитой данных.

По умолчанию используется неизменяемый уникальный `-pk`, доступный у всех
моделей. Для задач и подзадач сохраняется разрешённая сортировка по
неизменяемому `created_at`; совпадения уточняются по PK. При переходе
используются готовые `next` и `previous` из ответа без изменения фильтров
или сортировки. Изменение параметров начинает новую выборку.
Ответ содержит `next`, `previous`, `results`; общего `count` нет.

## Подготовка и запуск

Команды выполняются из папки проекта. Требуется Python 3.12 или новее.

```bash
uv venv --python 3.12 .venv
uv pip install --python .venv/bin/python -r requirements.txt
cp .env.example .env
```

В `.env` задаётся локальный `SECRET_KEY`. Для локальной записи SQL используется
`DEBUG=True`.

```bash
.venv/bin/python manage.py migrate
.venv/bin/python manage.py runserver 127.0.0.1:8787 --noreload
```

Для проверки переходов доступен набор из 13 демонстрационных задач
(команда предназначена для свежей учебной базы; фиксированные ID 1–13):

```bash
.venv/bin/python manage.py loaddata fixtures/tasks.json
```

Примеры маршрутов:

```text
/api/tasks/
/api/subtasks/
/api/categories/
/api/categories/count-tasks/
/api/tasks/statistics/
```

Сохранены CRUD, фильтры `status`, `deadline`, поиск `search`, сортировка
`ordering`, параметры `weekday` и `task_title`, мягкое удаление категорий и
назначение активных категорий задачам. Статистика и детальные ответы
возвращаются отдельными объектами и не требуют пагинации.

## Журналы

| События | Назначение |
| --- | --- |
| Работа локального сервера `django.server` | Консоль |
| Метод, путь и статус HTTP-запроса | `logs/http_logs.log` |
| SQL-запросы `django.db.backends` | `logs/db_logs.log` |

Папка `logs` создаётся автоматически. Файлы UTF-8 ограничены размером 1 MiB,
хранятся две резервные копии. HTTP middleware записывает также успешные
запросы; параметры URL, тела запросов, cookies и заголовки не записываются.
SQL-журнал работает при `DEBUG=True` и может содержать значения полей.
Локальные журналы, база, `.env` и окружение исключены из Git.

```bash
tail -n 10 logs/http_logs.log
tail -n 10 logs/db_logs.log
```

## Проверки

```bash
.venv/bin/python manage.py check
.venv/bin/python manage.py makemigrations --check --dry-run
.venv/bin/python manage.py test task_manager
```

Проверяются четыре коллекции, предел 6, полный проход вперёд без повторов,
обратный переход, ошибочный курсор, пустая выборка, фильтры, сортировка,
CRUD, статистика, мягкое удаление и фактическое разделение HTTP/SQL-журналов.

Проверено: все 6 групп тестов прошли. На локальном сервере проверены
переход между страницами, ответы 200/404 и запись HTTP/SQL в разные файлы.
