# Политика хранения учебных событий поиска и просмотра

**Принято 18.11.2026.** SearchEvent хранит нормализованную поисковую фразу, необязательную ссылку на User и время; ViewEvent — ссылку на Listing, необязательного viewer и время. IP-адреса, cookies и User-Agent не собираются. Анонимная запись не привязывается к конкретному пользователю. При авторизованном поиске фраза может содержать введённые самим пользователем сведения, поэтому запись рассматривается как потенциально персональная.

**Учебный срок хранения — 90 дней.** Это внутреннее инженерное решение, **не юридически обязательный срок**. После 90 дней истории и счётчики популярности больше не учитывают старые события. Публичные популярные фразы доступны только при трёх различных авторизованных искателях; такой порог уменьшает, но не устраняет риск раскрытия чувствительного текста. До реальной эксплуатации нужны уведомление пользователей, оценка законного основания, права удаления/доступа и пересмотр порога с учётом риска редких поисковых фраз.

Удаление выполняет `manage.py purge_statistics`: без флагов только подсчёт (dry run), `--days N` меняет срок (N >= 1), `--batch-size N` ограничивает размер транзакции, `--apply` разрешает реальное удаление. Пакеты удаляются в атомарных транзакциях, условие срока повторно проверяется при удалении. Индексы `created_at` добавлены миграцией statistics.0003. Запуск периодического задания **не настроен** — в учебной среде процедура выполняется вручную; автоматическое расписание относится к будущей инфраструктуре.

Сервис не удаляет Users, Listings, Bookings, Reviews, отзывы не теряют ссылки на состоявшееся проживание, soft delete объявлений продолжает сохранять исторические связи. Отдельный запрос на удаление личных событий потребует отдельной авторизованной процедуры до запуска с реальными пользователями; текущий механизм удаляет все устаревшие события независимо от автора.

Тесты: `tests/test_stage5.py` проверяет dry run, пакетное удаление, срок, сохранение целостности бронирований/отзывов/объявлений, приватные истории и публичные агрегаты. MySQL EXPLAIN подтверждает индексный диапазонный поиск по времени для удаления; индекс для ViewEvent также создан.
