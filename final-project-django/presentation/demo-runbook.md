## Стартовая среда

Демонстрация использует **локальный** `compose.yml`: Django `http://127.0.0.1:18765`, MySQL 8.4 в отдельном томе, миграции до старта API. Файл `.env` содержит локальные секреты и не входит в Git; значения из `.env.example` заполняются индивидуально. Инструкция по первой настройке и сохранности тома: [container-run.md](../docs/container-run.md).

Из корня репозитория:

```bash
docker compose config --quiet
docker compose up --build -d
docker compose ps
python3 infra/smoke_container.py
docker compose exec web python manage.py check
docker compose exec web python manage.py makemigrations --check --dry-run
```

При первом старте `db` проходит healthcheck, `web` применяет миграции. `docker compose down` останавливает только этот Compose-проект и **не удаляет** его volume. `down --volumes` не используется.

## Синтетические пользователи и реальный HTTP-сценарий

`seed_demo` не очищает базу, создаёт данные с доменом `example.invalid` и **не меняет пароли существующих пользователей**. Для сценария нужен новый seed (первый — `27177`), четыре Tenant, два Landlord, четыре объявления, восемь бронирований, без готовых отзывов и с шестнадцатью событиями. Первые бронирования соответствуют завершённому проживанию.

Без вывода пароля на экран используется временная переменная окружения терминальной сессии. Команды ниже используют Zsh; секрет передаётся через stdin в разовый процесс контейнера, не через аргументы и не через Git.

```bash
read -rs "DEMO_USER_PASSWORD?Temporary synthetic-demo password: "
echo
export DEMO_USER_PASSWORD
printf '%s\n' "$DEMO_USER_PASSWORD" | docker compose exec -T web sh -c 'IFS= read -r DEMO_USER_PASSWORD; export DEMO_USER_PASSWORD; exec python manage.py seed_demo --seed 27177 --landlords 2 --tenants 4 --listings 4 --bookings 8 --reviews 0 --events 16'
python3 infra/demo_flow.py --seed 27177
unset DEMO_USER_PASSWORD
```

`infra/demo_flow.py` использует стандартную библиотеку Python: отправляет реальные HTTP-запросы к контейнерному Django и **выводит только методы, пути, статусы и количество проверок**, не JWT, пароли или тела ошибок. Покрываются 401/403/404, Tenant/Landlord, собственность Listing и активация, поиск и ошибочный фильтр, PENDING/CONFIRMED/REJECTED/CANCELLED, конфликт 409 и повторное подтверждение, завершённая бронь → Review/рейтинг, защита чужого отзыва, история и публичная статистика, OpenAPI.

Второй запуск `seed_demo` с тем же seed не создаёт новых записей, но **HTTP-сценарий намеренно меняет состояние** (создаёт Listing, Booking, Review). Для полностью повторяемой защиты на уже использованной БД применяется **новый seed** в командах и параметре `--seed` сценария; удаление volume не требуется. Сохранённые синтетические данные остаются в контейнерной БД.

## Postman

В приватном workspace `Python Developer — Final Project (Django)` остаётся коллекция из **41 запроса в 8 папках**. Отдельный шаблон для Compose: [Django.docker.postman_environment.json](../postman/Django.docker.postman_environment.json). Он содержит `base_url=http://127.0.0.1:18765`, синтетические email для seed `27177`, пустые значения паролей/JWT/ID. Старое окружение `Django Final Project — Local (template)` на `8765` не меняется.

Импорт через Postman → Import → File → `postman/Django.docker.postman_environment.json`. Выбранное контейнерное окружение используется для последовательного запуска папки `Demo flow`; пароли обоих синтетических пользователей вводятся **только в приватный Postman environment**, JWT и идентификаторы заполняются тестовыми скриптами после успешных ответов. Демо из Postman создаёт **дополнительное** новое объявление и бронирование; для чистого повторного запуска нужен другой seed, новая пара синтетических пользователей или обоснованные новые тестовые даты.

В папке `Reviews` отдельный запрос требует `completed_booking_id` от завершённой CONFIRMED брони. Для seed `27177` Tenant `00000` может получить такую бронь через `GET /api/bookings/?scope=completed`; если сквозной `infra/demo_flow.py` уже создал по ней Review, повторное создание вернёт ожидаемый **409**, а не 201. Дата выезда не подделывается для обхода политики отзывов.
