# Менеджер задач — Generic Views

API задач и подзадач реализован через `ListCreateAPIView` и
`RetrieveUpdateDestroyAPIView`. Для обоих списков доступны фильтрация по статусу
и сроку выполнения, поиск по названию и описанию, сортировка по времени создания.

## Подготовка и запуск

Команды выполняются из папки проекта. Требуется Python 3.12 или новее.

```bash
uv venv --python 3.12 .venv
uv pip install --python .venv/bin/python -r requirements.txt
cp .env.example .env
```

В `.env` задаётся локальное значение `SECRET_KEY`. Затем выполняются миграции
и запуск сервера:

```bash
.venv/bin/python manage.py migrate
.venv/bin/python manage.py runserver 127.0.0.1:8782 --noreload
```

Адрес API: http://127.0.0.1:8782/api/tasks/.
Окружение, локальная конфигурация и база данных исключены из Git.

## Маршруты

| Метод | Маршрут | Назначение |
| --- | --- | --- |
| GET, POST | `/api/tasks/` | Список и создание задач |
| GET, PUT, PATCH, DELETE | `/api/tasks/<id>/` | Чтение, полное и частичное обновление, удаление задачи |
| GET, POST | `/api/subtasks/` | Список и создание подзадач |
| GET, PUT, PATCH, DELETE | `/api/subtasks/<id>/` | Чтение, полное и частичное обновление, удаление подзадачи |
| GET | `/api/tasks/statistics/` | Общее количество, распределение по статусам, количество просроченных задач |

Маршрут `/api/tasks/create/` сохранён как дополнительный адрес представления
списка и создания задач. Детали задачи содержат вложенный список подзадач.
Агрегирующее представление статистики сохранено без изменений.

## Фильтрация, поиск и сортировка

| Параметр | Пример | Поведение |
| --- | --- | --- |
| `status` | `new`, `in_progress`, `pending`, `blocked`, `done` | Точное совпадение статуса |
| `deadline` | `2026-12-15T12:00:00Z` | Точное совпадение даты и времени срока выполнения |
| `search` | `workshop` | Поиск по `title` и `description` без учёта регистра |
| `ordering` | `created_at` или `-created_at` | Сначала старые или сначала новые записи |

Параметры работают для задач и подзадач. Фильтры применяются совместно по
условию AND; затем выполняются поиск, сортировка и, для подзадач, пагинация.
При одинаковом `created_at` порядок уточняется по ID. По умолчанию сначала
показываются новые записи.

Параметр `deadline` сравнивает точный момент времени, а не календарный день.
При передаче часового смещения знак `+` должен кодироваться в URL как `%2B`;
`curl --data-urlencode` выполняет это автоматически.

```bash
curl --get 'http://127.0.0.1:8782/api/tasks/' \
  --data-urlencode 'status=in_progress' \
  --data-urlencode 'deadline=2026-12-15T12:00:00Z' \
  --data-urlencode 'search=workshop' \
  --data-urlencode 'ordering=-created_at'

curl --get 'http://127.0.0.1:8782/api/subtasks/' \
  --data-urlencode 'status=done' \
  --data-urlencode 'search=references' \
  --data-urlencode 'ordering=created_at'
```

Список задач возвращается массивом. Список подзадач сохраняет постраничный
формат `count`, `next`, `previous`, `results`, максимум по 5 объектов.
Параметр `page` выбирает страницу; `page_size` не увеличивает её размер.

Дополнительно сохранены параметры `weekday` для задач и `task_title` для
подзадач. `weekday` фильтрует по дню недели `deadline` в UTC: русское или
английское название либо число Django от 1 (воскресенье) до 7 (суббота).
`task_title` означает точное название главной задачи.

Неизвестный непустой статус и неверная дата возвращают HTTP 400.
Пустые `status` и `deadline` не ограничивают выборку. Отсутствующий объект
или страница возвращает HTTP 404. Отсутствие совпадений — HTTP 200 с пустым
массивом либо пустой страницей подзадач.

`id` и `created_at` не изменяются клиентом. При записи задачи переданный
`deadline` должен находиться в будущем. Связь подзадачи с задачей задаётся ID
существующей задачи. Удаление задачи каскадно удаляет её подзадачи.

```bash

.venv/bin/python manage.py makemigrations --check --dry-run
```

фильтрация, поиск по обоим полям, сортировка в обоих направлениях,
совместное применение параметров, пагинация, ошибочные значения,
статистика и HTML-интерфейс API. Все проверки прошли.
