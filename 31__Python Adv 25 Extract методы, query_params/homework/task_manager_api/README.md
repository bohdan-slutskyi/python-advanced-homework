# Менеджер задач — параметры запроса и пагинация

Django-проект содержит CRUD API задач и подзадач, фильтр задач по дню недели,
фильтры подзадач по главной задаче и статусу, а также постраничный вывод.

## Подготовка и запуск

Команды выполняются из папки проекта. Требуется Python 3.12 или новее.

```bash
uv venv --python 3.12 .venv
uv pip install --python .venv/bin/python -r requirements.txt
cp .env.example .env
```

В `.env` задаётся локальный `SECRET_KEY`. Затем выполняются миграции и запуск:

```bash
.venv/bin/python manage.py migrate
.venv/bin/python manage.py runserver 127.0.0.1:8776 --noreload
```

Для работы с административной панелью создаётся суперпользователь:

```bash
.venv/bin/python manage.py createsuperuser
```

Административная панель доступна по адресу `http://127.0.0.1:8776/admin/`.
Локальные настройки, база данных и окружение исключены из Git.

## Задачи по дню недели

`GET /api/tasks/` без параметров возвращает все задачи.

День недели определяется по **сроку выполнения `deadline`** в часовой зоне проекта
(UTC). В условии поле даты не задано; срок выполнения выбран как дата,
на которую запланирована задача.

Параметр `weekday` принимает русское или английское название дня независимо
от регистра и число в нумерации Django:

| День | Значение |
| --- | --- |
| Воскресенье | 1 |
| Понедельник | 2 |
| Вторник | 3 |
| Среда | 4 |
| Четверг | 5 |
| Пятница | 6 |
| Суббота | 7 |

```bash
curl --get 'http://127.0.0.1:8776/api/tasks/' --data-urlencode 'weekday=вторник'
curl 'http://127.0.0.1:8776/api/tasks/?weekday=tuesday'
```

Неверный или пустой `weekday` возвращает HTTP 400. Если подходящих задач нет,
возвращается пустой список с HTTP 200.

## Список подзадач

`GET /api/subtasks/` возвращает результат с полями `count`, `next`, `previous`
и `results`. Размер страницы фиксирован: максимум **5 объектов**. Параметр
`page_size` не изменяет этот предел. Номер страницы передаётся через `page`.

Объекты отсортированы по `created_at` по убыванию. При одинаковой дате
дополнительно применяется `-pk`, чтобы порядок страниц оставался определённым.

| Параметр | Назначение |
| --- | --- |
| `task_title` | Точное название главной задачи |
| `status` | Статус подзадачи: `new`, `in_progress`, `pending`, `blocked`, `done` |
| `page` | Номер страницы, начиная с 1 |

```bash
curl 'http://127.0.0.1:8776/api/subtasks/'
curl 'http://127.0.0.1:8776/api/subtasks/?page=2'
curl --get 'http://127.0.0.1:8776/api/subtasks/' --data-urlencode 'task_title=Prepare presentation'
curl 'http://127.0.0.1:8776/api/subtasks/?status=done'
curl --get 'http://127.0.0.1:8776/api/subtasks/' --data-urlencode 'task_title=Prepare presentation' --data-urlencode 'status=done'
```

Оба фильтра применяются совместно по условию AND, затем выполняется пагинация.
При отсутствии фильтров доступны все подзадачи с тем же порядком и пагинацией.
Неизвестное название задачи даёт пустую страницу с HTTP 200, неизвестный
статус — HTTP 400, несуществующая страница — HTTP 404.

## Сохранённые маршруты

| Метод | Маршрут | Назначение |
| --- | --- | --- |
| POST | `/api/tasks/create/` | Создание задачи с будущим сроком |
| GET | `/api/tasks/<id>/` | Детали задачи с вложенными подзадачами |
| GET | `/api/tasks/statistics/` | Статистика задач |
| POST | `/api/subtasks/` | Создание подзадачи |
| GET, PUT, PATCH, DELETE | `/api/subtasks/<id>/` | Работа с отдельной подзадачей |

## Проверки

```bash
.venv/bin/python manage.py check
.venv/bin/python manage.py makemigrations --check --dry-run
.venv/bin/python manage.py test task_manager
```

Проверки охватывают прежний CRUD и сериализаторы, все варианты фильтров,
границы страниц, ограничение размера страницы, порядок дат и ошибочные параметры.
