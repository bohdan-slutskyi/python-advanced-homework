# Менеджер задач — ORM-запросы

Проект продолжает модели Task, SubTask и Category с настроенной админкой,
уникальностью названий и историей миграций. ORM-запросы находятся в
`task_manager/presentation_queries.py`, а порядок их выполнения и вывод
результатов — в команде `presentation_crud`.

## Подготовка

Из этой папки:

```bash
uv venv --python 3.12 .venv
uv pip install --python .venv/bin/python -r requirements.txt
.venv/bin/python -c 'from pathlib import Path; import secrets; p=Path(".env"); p.exists() or p.write_text("SECRET_KEY=" + secrets.token_urlsafe(48) + "\nDEBUG=True\nALLOWED_HOSTS=127.0.0.1,localhost\n")'
.venv/bin/python manage.py migrate
```

## Выполнение и запись консольного вывода

```bash
mkdir -p logs
.venv/bin/python manage.py presentation_crud | tee logs/crud.txt
```

Команда создаёт задачу и две подзадачи, читает выборки, сохраняет изменения,
затем удаляет созданную задачу и её подзадачи. После успешного запуска
созданных записей в базе уже нет: это ожидаемый заключительный этап.
Команду можно повторить. Она не трогает другие задачи, категории и подзадачи.

Если записи с названиями упражнения уже есть, команда завершится ошибкой
без изменения данных. Весь сценарий выполняется в транзакции: ошибка
отменяет изменения; сообщения до ошибки ещё не означают успешную фиксацию.

Чтобы просмотреть этапы сохранённого консольного результата отдельно:

```bash
clear
sed -n '1,/3. UPDATE/p' logs/crud.txt
clear
sed -n '/3. UPDATE/,$p' logs/crud.txt
```

## Соответствие запросам

| Этап | Действие |
| --- | --- |
| Создание | Prepare presentation, описание и New; срок +3 дня |
| Создание подзадач | Gather information со сроком +2 дня и Create slides со сроком +1 день |
| Чтение | Все Task со статусом New |
| Чтение | Все SubTask со статусом Done и deadline раньше момента проверки |
| Изменение | Prepare presentation → In progress |
| Изменение | Gather information: deadline → два дня назад |
| Изменение | Create slides: описание → Create and format presentation slides |
| Удаление | Prepare presentation и связанные подзадачи через CASCADE |

В модели значения статусов: `new`, `in_progress`, `done`. Их отображаемые
названия — `New`, `In progress`, `Done`, как в условии. Фильтрация использует
значение, которое хранится в базе, вывод — `get_status_display()`.

Один `timezone.now()` задаёт опорный момент всего запуска, сроки рассчитываются
через `timedelta`. Это aware datetime в UTC. Относительные дни сохраняют время
суток, а не означают полночь календарной даты. В чистой базе выборка просроченных
Done-подзадач пуста: обе созданные подзадачи имеют New. Запрос всё равно
выполняется; положительный случай отдельно проверяется тестом.

## Проверки

```bash
.venv/bin/python manage.py check
.venv/bin/python manage.py makemigrations --check --dry-run
.venv/bin/python manage.py test task_manager
```

Тесты используют временную базу: проверяют точные поля и сроки, обе выборки,
изменения, каскадное удаление, сохранность других записей и отказ при совпадении
названий. Рабочая база, `.env` и окружение исключены из Git.

Для этих консольных упражнений запуск сервера и создание администратора не нужны.

## Результат выполнения

На Python 3.12.13 / Django 6.1.1 успешно прошли все 8 тестов.
`check` не обнаружил ошибок; `makemigrations --check --dry-run` не обнаружил
изменений схемы. Сценарий выполнен на отдельной рабочей базе.

Полный фактический вывод сохранён в [logs/crud.txt](logs/crud.txt):
созданы одна задача и две подзадачи, прочитаны обе выборки, сохранены три
изменения, затем удалены три объекта. В конце созданных записей нет:
`Task=0, SubTask=0`.

Для скриншотов откройте обычную консоль в папке проекта и покажите две части
`logs/crud.txt` командами выше. Первый кадр должен содержать CREATE и READ,
второй — UPDATE и DELETE. Сохранённый лог — текстовый результат выполнения;
он не заменяет требуемые скриншоты консоли.
